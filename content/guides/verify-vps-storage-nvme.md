<section class="page-hero"><p class="eyebrow">HOSTING GUIDE</p><h1>How to verify VPS storage is really NVMe before you pay for the label</h1><p class="lede">An "NVMe" label on a plan page does not always mean what a buyer imagines. Read the wording, ask the provider before checkout, and run a few checks inside the server — and treat any single test as evidence, not proof.</p></section><article class="prose"><h2>The short answer</h2>
<p>Verify NVMe storage in three stages. First, read the plan page and the terms: look for the exact storage type, whether it is local or network-attached, and whether the label covers the boot disk, extra volumes, or both. Second, ask pre-sales support the five questions below and keep the answers. Third, after the server is running, check the disk device name and type inside the server. If the plan page is vague, support will not answer in writing, or the in-server checks contradict the label, do not pay the NVMe premium — buy the cheaper plan or pick a provider that documents storage clearly.</p>
<p>One warning before the details: no check a buyer can run proves the full speed of a shared host. On a VPS, neighbours share the same hardware, so even genuine NVMe hardware can feel slow at busy times. What you can verify is the storage type the provider assigned to your server, not a guaranteed speed.</p>
<h2>Start with the words on the plan page</h2>
<p>Marketing pages use several phrases that sound alike but mean different things. Read them literally.</p>
<div class="table-wrap"><table><thead><tr><th>What the page says</th><th>What it usually means</th><th>What to check</th></tr></thead><tbody>
<tr><td>NVMe SSD storage</td><td>Flash storage on an NVMe interface</td><td>Does it cover the boot disk and any extra volumes?</td></tr>

<tr><td>NVMe cached / NVMe accelerated</td><td>Only a cache layer may be NVMe; the main disk may be slower</td><td>Ask what the main disk itself is</td></tr>

</tbody></table></div>
<p>Also check whether the storage is local to the host machine or attached over the network. Network-attached storage can still use NVMe drives at the other end, but it adds a network hop and its behaviour differs from a local disk. A plan page that says nothing about this has left out a basic fact, not a detail.</p>
<p>For the background on what storage type changes in practice, read our <a href="/guides/nvme-ssd-hdd-vps-storage/">NVMe, SSD and HDD comparison</a> first: for a cached static site the disk barely matters, while for a database-backed site it is part of the daily experience.</p>
<h2>Five questions to ask support before checkout</h2>
<p>Send these before you pay, and save the reply. A provider that answers clearly is already a good sign; a provider that answers with more marketing language is telling you something too.</p>
<p><strong>1. Is the boot disk local NVMe, or network-attached storage?</strong> This is the single most informative question. Local and network-attached storage behave differently under load and during host maintenance.</p>
<p><strong>2. Does the NVMe label cover the included disk, or only extra volumes I buy separately?</strong> Some plans advertise NVMe for add-on volumes while the included disk is ordinary SSD.</p>
<p><strong>3. Is the disk shared with other customers on the same host?</strong> On a VPS the honest answer is almost always yes. What matters is whether the provider says so plainly instead of implying dedicated hardware.</p>
<p><strong>4. Can I add storage later without rebuilding the server?</strong> This decides whether a small start is reversible. A plan that forces a rebuild to grow is a different commitment from one that lets you attach a volume.</p>
<p><strong>5. If the delivered disk type does not match the plan page, what happens?</strong> Ask this before checkout, not after. Note the refund or credit terms the provider points to — this guide does not invent a refund window, because terms differ by provider.</p>
<h2>Three checks inside the server</h2>
<p>These checks use standard Linux tools on the server itself. They work on a typical Linux VPS; if your server runs another system, ask support for the equivalent output rather than guessing.</p>
<h3>Check 1: the device name</h3>
<p>Run <code>lsblk</code> and look at the disk device names. A local NVMe disk normally appears as something like <code>nvme0n1</code>, while a SATA or virtual disk appears as <code>sda</code> or <code>vda</code>. A name starting with <code>nvme</code> is positive evidence. A name starting with <code>vd</code> or <code>sd</code> does not automatically mean the provider lied — virtualised disks can hide the underlying hardware — but it does mean the device name alone cannot confirm NVMe, and you should move to checks 2 and 3 and ask support.</p>
<h3>Check 2: the transport and rotation flags</h3>
<p>Run <code>lsblk -d -o NAME,TRAN,ROTA</code>. The <code>TRAN</code> column shows the transport: <code>nvme</code> for an NVMe device. The <code>ROTA</code> column shows whether the disk rotates: <code>0</code> means non-rotating, which fits flash storage, while <code>1</code> means a spinning disk. A result of <code>TRAN=nvme, ROTA=0</code> matches an NVMe flash disk. A result of <code>ROTA=1</code> on the main disk contradicts any NVMe or SSD label — raise it with support before doing anything else. Note that virtual disks often show an empty <code>TRAN</code> value; again, that is inconclusive, not a verdict.</p>
<h3>Check 3: a small before-and-after comparison, not a benchmark score</h3>
<p>Do not trust a single speed number, and do not quote one as proof: shared hosts vary by time of day, neighbours and caching, so one test result proves little. If you still want a comparison, run the same small read/write test at two different times and compare the results with each other, or compare a new server with the old one you are replacing. A test that collapses at busy times tells you about contention on the shared host, not about the disk label — and that is useful information for the buying decision even though it is not a hardware verdict. Run tests only on an empty test server, never as a stress test on a live site, and delete test files afterwards.</p>
<h2>Red flags that should stop a purchase</h2>
<p><strong>The plan page and the checkout page disagree.</strong> If one says NVMe and the other says SSD, the cheaper description is the one to believe until support corrects it in writing.</p>
<p><strong>Support will not name the disk type.</strong> "High-performance storage" is not an answer to a direct question about NVMe. Vague answers before purchase predict vague answers after a problem.</p>
<p><strong>The label covers only a cache.</strong> A fast cache in front of slow storage helps repeated reads and does little for writes, backups and database work.</p>
<p><strong>The premium is large and the workload is light.</strong> If the site is mostly cached static pages, the NVMe premium buys little even when the label is true. Size the whole server first with our <a href="/guides/how-to-choose-first-vps/">first VPS guide</a>, then decide whether storage is the line worth paying more for.</p>
<h2>What to do if the checks contradict the label</h2>
<p>First, re-check: confirm you tested the main disk and not a temporary or add-on volume, and confirm the commands ran on the server you bought rather than a local machine. Second, send support the exact command output and ask for a correction or an explanation. Third, if the answer is unsatisfactory, use the refund or cancellation terms you noted before checkout — that is why question 5 comes before payment, not after. Keep the plan page wording, the support reply and your command output together; they are the evidence if the dispute goes further.</p>
<h2>Before you pay</h2>
<p>Work through the plan in this order: compare the whole plan, not just the storage line, with our <a href="/guides/how-to-choose-first-vps/">first VPS guide</a>; read the <a href="/guides/how-to-read-vps-promo-terms/">promotion checklist</a> so a discounted first term does not hide a storage downgrade at renewal; and check the <a href="/compare/">verified offer comparison</a> for current plans. A clear label, a written support answer and in-server checks that agree are worth more than any speed claim on a sales page.</p>
