<section class="page-hero"><p class="eyebrow">AI UPDATE / READING THE NEWS</p><h1>"Open weights" is not the same as "open source."</h1><p class="lede">A headline that calls a model "open" may mean only that its trained weights are downloadable. The code, the training data and the right to use it commercially are separate questions — and each one can have a different answer.</p></section><article class="prose"><h2>Why the word "open" misleads</h2><p>An AI release is not one thing. It is a bundle of parts, and a publisher can release some parts while keeping others private. News coverage often shortens that bundle to a single word, "open," which hides exactly the parts a builder needs to know about. Two releases described with the same word can therefore come with very different rights and very different work.</p><p>The confusion is understandable: in traditional software, "open source" has a settled meaning — the source code is published under a licence that lets you use, study, change and share it. A trained AI model adds a part that traditional software does not have: the weights, the vast set of numbers produced by training. Publishing the weights is not the same as publishing the source code, and neither one automatically includes the training data.</p><h2>The four parts, separated</h2><div class="table-wrap"><table><thead><tr><th>Part</th><th>What it is</th><th>What "published" does and does not mean</th></tr></thead><tbody>
<tr><td>Weights</td><td>The trained numbers that make the model behave as it does</td><td>Downloadable weights let you run or adapt that trained model; they do not explain how it was trained</td></tr>
<tr><td>Code</td><td>The programs for training, running and evaluating the model</td><td>Published code lets you inspect and change the machinery; it does not by itself give you a trained model</td></tr>
<tr><td>Training data</td><td>The material the model was trained on</td><td>Rarely published in full; a description of the data is not the data itself</td></tr>
<tr><td>Licence</td><td>The legal terms for using, changing and sharing the parts above</td><td>The licence, not the headline, decides commercial use, redistribution and attribution</td></tr>
</tbody></table></div><p>A release can therefore be "open weights" while its code is unpublished, its data undisclosed and its licence restrictive — or it can be fully open on all four parts. The headline alone cannot tell you which one you are looking at.</p><h2>Four checks before you trust the label</h2><ol><li><strong>Read the licence, not the announcement.</strong> Look for what it permits: personal use only, or commercial use too? May you redistribute the weights, or only use them yourself? Must you credit the publisher, and must modified versions carry the same terms? If the announcement does not link a licence, treat the release as unpriced, unlicensed territory: usable for reading about, not yet safe to build a product on.</li><li><strong>Ask what exactly is downloadable.</strong> Weights alone, weights plus code, or weights plus code plus evaluation tools? Each missing piece is work you must supply yourself, from writing the serving code to building your own tests.</li><li><strong>Separate "downloadable" from "free to run."</strong> Downloading weights costs nothing in itself, but running a large model needs hardware with enough memory, and that hardware is rented or bought. A model you can download is not a model you can run on an ordinary laptop, and a hosted version of the same model is a different product with its own price and terms. Compare the two before choosing, as in <a href="/guides/ai-subscription-vs-api/">subscription versus API billing</a>.</li><li><strong>Check whether "open" covers the version you actually want.</strong> Publishers sometimes release a smaller model openly while keeping the largest version behind an account or a paid plan. Confirm the size, capabilities and licence of the exact version you plan to use, not of the model family in general.</li></ol><h2>What this means for a small project</h2><p>For a website builder, the practical question is rarely philosophical. It is: can I use this model in my project, under what terms, and at what running cost? A downloadable model gives you control — you can run it on your own server, keep prompts private and avoid per-request billing — but it also gives you responsibility: hosting, updates, safety checks and scaling are yours. A hosted model removes that work but keeps your project dependent on the provider's price, availability and terms.</p><p>Neither choice is wrong in general. The mistake is choosing on the strength of the word "open" and discovering the licence or the hardware bill afterwards. Read the licence first, confirm the exact version, and test with the workload you actually plan to run, following <a href="/guides/evaluate-new-ai-model/">the model evaluation checklist</a>.</p><p>For background on running models through hosted endpoints rather than your own server, see <a href="/ai-tools/hugging-face-inference-endpoints/">the inference endpoints guide</a>.</p></article><section class="prose"><h2>Sources and review scope</h2><p>This is a general terminology guide, not a review of any specific release: it names no product, states no price or plan limit, and makes no claim about any particular model's licence or availability.
