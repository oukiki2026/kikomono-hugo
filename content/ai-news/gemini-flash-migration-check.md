<section class="page-hero"><p class="eyebrow">AI UPDATE / GOOGLE</p><h1>Check access before you switch Gemini models.</h1><p class="lede">Google's dated API notices are useful for choosing a model identifier. They do not replace testing your application's behavior.</p></section><article class="prose"><h2>What the official record says</h2><p>Google's release notes dated September 2, 2026 announce general availability of Gemini 3.8 Flash, with the identifier <code>gemini-3.8-flash</code>. The September 18 notice says access to Gemini 2.5 models is limited to users who previously used them; it also says those models are not deprecated and recommends newer models for new projects. The notices describe access, not a comparison of model performance.</p><p><a href="https://ai.google.dev/gemini-api/docs/changelog" rel="noopener">Read the official dated release notes</a> and <a href="https://ai.google.dev/gemini-api/docs/models" rel="noopener">current model documentation</a>. Source review: 2026-10-02. This article covers those specific notices and does not claim to list every subsequent announcement.</p><h2>Why this matters to a website builder</h2><p>If a tutorial points to an older model, do not assume your new project can access it. Check the exact model identifier against current documentation and your account's permitted access. An access limitation is different from retirement: changing the error handling and replacing the entire application are different responses. This distinction can prevent unnecessary rewrites.</p><h2>Our suggested migration check</h2><p>Keep the existing configuration recorded and work in a test environment. Confirm the model accepts your input format, returns the output your parser expects and supports any tools you use. Run representative requests, including failure cases. Compare the complete task rather than a single impressive answer. Use the test results to decide whether switching helps your app.</p><p>Review the current pricing for the exact model and features before enabling public usage. Set an application spending limit and decide what happens when requests fail or retry. Do not assume an editor subscription includes API calls from visitors, or that the server hosting the website runs the remote model itself.</p><h2>Before making it public</h2><p>Check both success and rejection paths, keep private API keys out of browser code and prepare a rollback. Preserve only the logs necessary to investigate failures; do not turn testing into a new collection of private user prompts. Check the official notes again when you deploy, because this page is a dated editorial review rather than live account information.</p><p>Continue with <a href="/guides/evaluate-new-ai-model/">the model evaluation checklist</a>, <a href="/guides/ai-subscription-vs-api/">subscription versus API billing</a> and <a href="/ai-tools/ai-app-budget/">the application budget guide</a>.</p><p>Source links are non-affiliate links.
